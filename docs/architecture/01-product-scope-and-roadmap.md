# 产品边界与迭代路线

## 定位

最终产品是可上线的巡检诊断 Agent：从真实遥测系统取证，关联异常，提出有证据支持的根因候选，后续通过人工授权执行白名单降级或熔断，并验证结果、保存审计和案例。

技术方向为 TypeScript、Node.js 20、pnpm。部署工具链的版本兼容性在实施阶段验证；不能仅凭 package.json 的 engines 声明认定环境兼容。模型先接 OpenAI-compatible 协议，首个实际供应商选择 DeepSeek。

## V1 范围

- 单用户本地开发验证，actor 为 local-user；Docker Compose 启动遥测实验环境。
- 通过独立 Agent Web 使用 Agent，通过独立 Simulator Web 管理模拟场景。
- 模拟器产生遥测，真实 Prometheus、Elasticsearch 和 Tempo 保存并提供查询；Agent 通过 MCP Tool 取证。
- 支持手动、定时、Alertmanager 三类触发，统一进入 InspectionTrigger。
- 第一黄金场景：结算失败率升高，日志和 Trace 指向 MySQL 超时。
- 输出结构化诊断以及口语化详细摘要；明确事实、假设、缺失证据和建议。
- 支持数据源超时、重试、熔断、部分结果、Checkpoint，以及 LangSmith 执行链路与评测。

V1 验收不依赖 group-buy-market 在线运行，不修改其业务代码。该项目仍为后续首个真实业务接入目标。模拟遥测经真实后端查询，代表接入链路可验证，不代表真实业务故障已经验证。

## 阶段边界

V1 生产组装不注册 Bash、任意 HTTP/SQL 写工具、外部端侧执行和真实保护动作。框架可以保留这些抽象及安全测试。Git/代码阅读、变更 Subagent、多人权限、正式经验晋级、真实动作都在后续阶段。

## 实施里程碑

| 阶段 | 可验收产物 |
|---|---|
| V1.1 遥测实验室 | 可重复的正常/故障场景，三种后端可查询，关联字段一致 |
| V1.2 能力接入 | Registry、MCP、四道闸门、重试和三类 Subagent 的契约测试 |
| V1.3 手动诊断闭环 | Agent Web 发起任务，流式进度、证据回查、结构化报告 |
| V1.4 可靠运行 | 定时与告警入口、去重、恢复、数据源熔断、取消与预算 |
| V1.5 交付评测 | LangSmith 数据集、故障注入测试、Compose 文档与验收记录 |

各里程碑单独形成实施计划，避免把整个产品作为一次不可验证的大改动。
