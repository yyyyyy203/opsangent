# Agent Web MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让个人开发者通过浏览器完成发起巡检、观察调查、查看证据、处理确认和恢复历史 Run 的闭环。

**Architecture:** Web 仅调用 HTTP 查询/命令与 Public V2 SSE；业务状态仍由 Harness、HITL 和持久化层负责。新增小接口而不扩大 Harness；消息以持久化公开快照为准，SSE 用于进度通知和查询失效，不直接把重放 delta 追加到消息正文。

**Tech Stack:** 沿用 TypeScript、Node.js 20、pnpm、SQLite、Vitest；浏览器端建议 React + Vite，独立 tsconfig。新增开发依赖须在安装时核对 Node engine，固定兼容版本，不使用未经检查的 latest，不顺手升级 Node 或 pnpm。

**Spec:** `docs/superpowers/specs/2026-10-01-run-evidence-read-api.md` 是已有查询边界；本文“设计增量”是待确认的 Web/HITL 接口提案，不代表已有实现或已经发布的契约。

## Global Constraints

- 仅本地个人验证；Agent HTTP 默认 `127.0.0.1`，不得声称可公网部署。
- Agent 页面和模拟器管理分离；本次不新增模拟器页面或模拟场景控制接口。
- 既有 Event/Message V2、ToolResponse 与 checkpoint 语义不破坏性修改。
- 命令走显式服务，禁止 SSE/EventBus 作为确认、启动、恢复的命令入口。
- 真实写操作不开放；确认测试使用只读工具的测试 Hook，不为演示开放 Bash 或真实降级动作。
- 前端不接触 API Key、MCP 凭据、原始日志、内部模型请求或 AgentContext。
- 每个任务必须先写失败测试、验证失败、最小实现、验证通过，再单独提交；不自动 push。

## 设计增量

### 1. 界面和边界

单页面：左侧 Run 历史，中间任务输入与消息，右侧状态、子调查和证据详情。内容较窄时右侧变抽屉，不依赖三栏才能操作。

首版包括：选择已配置 Profile、输入问题、启动、分页历史、公开消息、工具状态、子 Run 详情、诊断/缺失证据、证据摘要、确认/拒绝、显式恢复、连接错误提示。没有真实数据时显示缺失或失败，不用伪造正常结论填空。

### 2. 新增接口

沿用 `{ error, message }` 错误外形，新增稳定错误码。404 不存在；400 输入不合法；409 状态/版本冲突；410 确认过期；503 服务未组装。内部异常统一脱敏。

| 接口 | 输入/输出 | 约束 |
| --- | --- | --- |
| `GET /profiles` | 已启用 Profile 的 id、名称、说明、只读能力状态 | 禁止返回连接地址和凭据 |
| `GET /runs/:id/messages?cursor=&limit=` | `PublicMessagePage` | 默认20、最大50，按 createdAt/id 倒序 keyset，单页总上限512KiB |
| `GET /runs/:id/confirmation` | `PublicConfirmation \| null` | 从当前 checkpoint 投影，不从旧 SSE 推导待确认状态 |
| `POST /runs/:id/confirmation` | `{toolCallId, confirmed, expectedRevision, reason?}` | actor/decidedAt 由宿主注入；校验必须与保存的 CAS 绑定 |
| `POST /runs/:id/resume` | 原路径，返回202或明确冲突 | 只恢复可恢复 Run，不隐式创建，不并发重复运行 |

新端口放在 `contracts/web-read-model.ts`，不强迫所有现有 MessageStore 实现新增必选方法：

```typescript
interface MessagePageOptions { cursor?: string; limit?: number }
interface PublicMessageItem {
  message: AgentMessageV2; // 仅 PublicMessageProjectorV2 的输出
  version: number;
  truncated: boolean;
}
interface PublicMessagePage {
  items: readonly PublicMessageItem[];
  nextCursor?: string;
}
interface WebMessageQueries {
  listMessages(runId: string, options?: MessagePageOptions): Promise<PublicMessagePage>;
}
interface PublicConfirmation {
  runId: string;
  toolCallId: string;
  expectedRevision: number;
  summary: string;
  expiresAt?: string;
}
```

上述类型导入现有 `AgentMessageV2`。公开文本截断须显式标记；单消息上限64KiB，保留身份、状态与安全提示，不切断 JSON 字节后直接输出。原始消息保留不变。不能通过“先全量 listMessagesByRun 再 slice”实现分页；SQLite 使用有界 SQL，内存适配器维护按 Run 索引。需要索引时新增事务迁移，不修改旧迁移。

确认门面调用既有 HitlService；批准/拒绝与恢复分两个命令。现有 decide 在过期时保存拒绝结果后正常返回，HTTP 必须返回 expired，而不能仅凭没有抛错宣称批准。允许通过新增内部结果方法保留原有 `decide(): Promise<void>` 兼容包装。不得仅在 API 层先读 revision 再无条件 decide。

### 3. 流式与恢复策略

选用“快照替换 + SSE 通知”作为首版，不选择“纯轮询”或“前端全量事件重建”。纯轮询缺少即时进度；完整事件重建需要解决 transient 过期和快照水位协议，超出本次必要范围。

1. 打开 Run 后立即读取详情、最近消息、证据目录、待确认项，同时订阅 SSE。
2. SSE 触发可见消息页刷新，200ms 合并窗口，同资源最多一个在途请求；处理中再次失效则请求完成后补刷新。
3. 消息按 messageId/version 整条替换，较旧版本不得覆盖较新版本。SSE delta 和旧 `message_snapshot` 不追加正文。由此提供近实时增长文本，不承诺逐 token 原样显示。
4. 模型消息投影与 SSE 通知可能并行，单次通知后的读取未必最新；运行期间每2秒校准一次，终态后继续校准，直到最新公开消息为终态。最多10秒；仍未收敛则提示“消息同步未完成”并提供重试，禁止假装完整。
5. 重连游标失效时重新查询快照、从新连接继续，不重放 POST。刷新页面不会自动调用 resume。
6. 子 Run 不共享父 SSE 序列；通过 childRunIds 展示卡片，只有展开的子 Run 建立订阅；最多同时4个。未展开的子 Run 随父详情校准，详情尚未持久化时显示“准备中”。
7. SSE `liveQueue` 上限256事件/1MiB，溢出断开慢连接并要求快照重同步，不静默丢弃终态。重放与 live 以已发送序列高水位去重，替换无界 Set；乱序必须检测，不可悄悄跳过。
8. HTTP 验证 Run/cursor 后立即发送响应头；response.write 返回 false 时等待 drain，客户端断开则取消等待并清理订阅。catch-up 每批检查 Abort；15秒心跳，定时器可注入。

保留旧 `/events` 默认快照行为。新增 `snapshots=none` 查询模式供 Web 使用，只省略兼容快照帧，不改变公开 V2 事件；这样新 Web 不会触发旧快照全量读取。旧消费方的全量快照问题不因此被宣称已解决。

### 4. 本地宿主安全与执行协调

独立宿主在 bootstrap 组装 SQLite、模型、已配置只读工具、查询和 HITL；启动前 await runtime.ready。前端构建不包含任何模型密钥。

单进程 `RunExecutionCoordinator` 包住启动/恢复/确认操作，按 runId 互斥，并依赖持久化 revision 检查；这不是分布式锁。旧 checkpoint 或未组装 durable HITL 时，确认 API 返回503，不降级为无版本授权。

浏览器写请求仅允许配置的精确 Origin，校验 Host 防 DNS rebinding，并要求 JSON；开发代理必须保留或显式转换到配置的受信 origin，不接受任意反射。CORS 不是认证，本增量不支持远程或多用户。

启动请求使用浏览器生成并保留的 runId 作为本次提交标识；响应不确定时先查询此 runId，禁止另造 ID 自动重发。Coordinator 在启动接受时登记 pending/active；查不到 checkpoint 不等于该 ID 从未受理。终态重复启动返回409，不重新执行。
